a.2 · recovering homographies

a homography p' = Hp has 8 unknowns once h33 is set to 1. each correspondence (x, y) → (x', y') gives two rows of Ah = b:

[ x  y  1  0  0  0  -x'x  -x'y ] h = x'
[ 0  0  0  x  y  1  -y'x  -y'y ] h = y'

with more than 4 points it's overdetermined, so i solve it with least squares.

def computeH(im1_pts, im2_pts):
    A, b = [], []
    for (x, y), (u, v) in zip(im1_pts, im2_pts):
        A.append([x, y, 1, 0, 0, 0, -u * x, -u * y])
        A.append([0, 0, 0, x, y, 1, -v * x, -v * y])
        b += [u, v]
    h = np.linalg.lstsq(np.array(A), np.array(b), rcond=None)[0]
    return np.append(h, 1).reshape(3, 3)

i used 12 points per pair. to pick them, i took sift matches, kept the ones that agreed with each other under a ransac loop over computeH, and then chose 12 that were spread out.

for this pair A is 24 x 8. the recovered H, taking the left image into the right one:

a.3 · warping the images

inverse warping. for every output pixel, map back through H⁻¹ and sample the source, so there are no holes. the output size comes from pushing the four corners through H, and pixels that map outside the source get alpha 0. (0, 0) is the center of the top left pixel. nearest neighbor rounds to the closest source pixel, and bilinear takes a weighted average of the 4 pixels around the point.

def _bilinear(im, sx, sy):
    h, w = im.shape[:2]
    ok = (sx >= 0) & (sx <= w - 1) & (sy >= 0) & (sy <= h - 1)
    x0 = np.clip(np.floor(sx).astype(int), 0, w - 2)
    y0 = np.clip(np.floor(sy).astype(int), 0, h - 2)
    fx, fy = (sx - x0)[..., None], (sy - y0)[..., None]
    top = im[y0, x0] * (1 - fx) + im[y0, x0 + 1] * fx
    bot = im[y0 + 1, x0] * (1 - fx) + im[y0 + 1, x0 + 1] * fx
    vals = top * (1 - fy) + bot * fy
    vals[~ok] = 0
    return vals, ok

rectification

mark the four corners of something rectangular and send them to a rectangle, sized from the average lengths of opposite sides. i only warp a box around the rectangle, since the rest of the plane gets stretched toward its vanishing line. the full window warp was 22814 x 24373.

the window side of the house now faces the camera. the gate was shot almost straight on, so it only gets a small fix.

nearest vs bilinear

in the rectifications the two look about the same, since the scale is close to 1 and the edges end up straight. warping the rotated keyboard shot into the middle one makes straight edges diagonal, and that's where they differ.

nearest gives stair steps along the key edges and bilinear stays smooth. bilinear was 3.6x slower on the full 18.6 MP warp (2.30 s vs 0.65 s), and 3.5x and 3.8x slower on the window and gate (0.14 s vs 0.04 s, 0.57 s vs 0.15 s). i used bilinear for everything else.

a.4 · blending into a mosaic

all the images get warped into one frame, each carrying a weight that is 1 at its center and falls to 0 at its edges (distance transform). then a 2 level blend. the low frequencies (gaussian, σ = 8) are a weighted average of every image, and the high frequencies come only from the image with the highest weight at that pixel. brightness changes get smoothed over the overlap, but fine detail never gets averaged into ghosts.

high[sl][take] = (img - lo)[take]
